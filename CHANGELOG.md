# Changelog

## Unreleased

- `tfs-doc-automation-mvp`: a queued work item could stall with the dashboard logging `Agent result status: waiting` and no visible error. The packaged `.vsix` was never rebuilt after `extension.js` gained `dispatch_only` support, and the post-create force-installed it over the correct source it had just copied; the builder also wrote a malformed `[Content_Types].xml` and no `extension.vsixmanifest`. On failure the bridge wrote `agent-result.json` into the dispatch package, which the dashboard never reads and which permanently hid that package from `runPendingJobs`, and `_queue_vscode_bridge_job` cleared the dispatch state file but not that result. The post-create now rebuilds the package from source before installing, dispatch failures report through `bridge-job-state.json` and `bridge-status.json` only, and the stale result is cleared on queue.
- `tfs-doc-automation-mvp`: `claude_cli` is a first-class provider. It builds its own bounded non-interactive command (binary resolved from `PATH`, the npm global prefix, then `npx @anthropic-ai/claude-code`), translates dashboard display names into the model IDs the CLI accepts (`Claude Haiku 4.5` is `claude-haiku-4-5`), and gets the result recovery that was `copilot_cli`-only. A `CLI Command Template` is no longer required, and one set in Settings still wins. It provisions no credential: supply one before selecting the provider.

- `tfs-doc-automation-mvp`: the pipeline no longer needs a checkout of `CM-AI-Content-Skills`. The shared assets are an APM package installed straight into the portal from `CONTENT_AI_APM_DEPENDENCY`, so the image seed, the writable runtime copy and `CONTENT_AI_REPO_PATH`, `CONTENT_AI_IMAGE_REPO_PATH`, `CONTENT_AI_REPO_URL` and `CONTENT_AI_BRANCH` are gone from the post-create, bootstrap and image contracts; images ship the `apm` CLI and set `CONTENT_AI_APM_INSTALL_CLI=false`.
- `tfs-doc-automation-mvp`: shared Content AI assets are now installed with APM, following the `CM-AI-Content-Skills` 1.0 contract. `scripts/sync-content-ai-assets.sh` runs `apm install`/`apm compile` (honoring a committed portal `apm.yml`, or generating a git-excluded one pointing at the published `main` branch until a release tag exists), cleans up the previous `.agents/content-ai` + dotagents layout, and the pipeline's instruction discovery reads `.github/instructions/` and `.claude/rules/`. `CONTENT_AI_SYNC_ROOT_AGENTS` and `CONTENT_AI_DOTAGENTS*` are gone; `CONTENT_AI_APM_VERSION`, `CONTENT_AI_APM_DEPENDENCY` and `CONTENT_AI_APM_INSTALL_CLI` replace them.
- `tfs-doc-automation-mvp`: application log with reference ids, persisted runner health with `GET /health`, per-work-item diagnostics viewer and bundle, and machine-readable agent result codes.
- `tfs-doc-automation-mvp`: removed the `m365_desktop` provider and other dead code; README and technical design aligned with shipped behavior; added maintainers and user guides; `CONTENT_AI_WORKSPACE_ROOT` replaces the hardcoded `/workspaces`.

## 0.1.0 - 2026-08-31

- Created the repository as the home for the Content Team's internal AI tools.
- Moved `tfs-doc-automation-mvp` here from `CM-AI-Content-Skills/projects/` with its full commit history.
- Split the runtime contract into two checkouts: the tools repository (`CONTENT_AI_TOOLS_REPO_PATH`, default `/workspaces/CM-AI-Content-Tools`, seeded from `CONTENT_AI_TOOLS_IMAGE_REPO_PATH`) and the shared-assets repository (`CONTENT_AI_REPO_PATH`, default `/workspaces/CM-AI-Content-Skills`). The bootstrap and post-create scripts clone, refresh, and validate both.
